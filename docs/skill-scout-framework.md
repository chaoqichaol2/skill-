# Skill Scout 推荐框架

## 更新节奏

- 每天 09:00 收集并刷新候选池。
- 每两天评测并发布 1 个主推荐。
- 没有达到门槛的候选时，明确发布“本期无推荐”，不为保持频率凑数。

## 入池条件

候选至少满足以下条件：

1. 有可核验的来源、安装方式和使用说明。
2. 能对应一个具体任务，而不是只有概念介绍。
3. 最近仍可用；仓库、插件或作者页面没有明显失效。
4. 不要求用户交出不必要的敏感权限。

## 五维评分（10 分制）

| 维度 | 权重 | 判断问题 |
| --- | ---: | --- |
| 真实提效 | 30% | 是否明显减少重复操作、等待或返工？ |
| 结果可靠 | 25% | 同类任务能否稳定复现，失败边界是否清楚？ |
| 上手成本 | 15% | 安装、授权和学习成本是否与收益匹配？ |
| 适用广度 | 15% | 是否能覆盖多个高频场景或角色？ |
| 维护活跃 | 15% | 文档、版本、问题反馈和更新是否健康？ |

综合分低于 8.0 不推荐；8.0–8.7 进入观察；8.8 以上才可成为主推荐。

## 实测要求

主推荐必须写清：

- 最适合谁，以及最适合的一个任务。
- 用它完成该任务的最短步骤。
- 节省了什么时间或减少了什么操作。
- 至少一个限制、失败点或不适用场景。
- 源码或官方页面、安装说明和最近核验日期。

## 发布结构

每一期固定使用以下结构：

1. 一句话结论。
2. 适合谁 / 不适合谁。
3. 3 个真实使用场景。
4. 五维评分与证据。
5. 安装和开始使用的最短路径。
6. 风险、权限与替代方案。
7. 下一期候选观察池。

## 编辑原则

- 推荐结论优先于热度。
- 真实任务优先于功能数量。
- 证据优先于宣传文案。
- 不确定就标注，不虚构“实测”。
- 来源失效或结果明显退化时，下架或更正旧推荐。
